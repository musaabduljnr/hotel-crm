# Supabase integration plan

This project is now prepared to support Supabase as an alternate runtime backend while keeping the current MySQL-first app functional.

## Current state
- Backend currently relies on MySQL via `mysql2`
- JWT auth is present in Express middleware
- Frontend expects an API backend endpoint via `REACT_APP_API_URL`
- Supabase client libraries are now added to frontend and backend for future integration

## Recommended migration path

### 1) Create Supabase project
- Create a new Supabase project in the dashboard
- Copy the project URL and anon/service keys to `.env`

### 2) Create database schema in Supabase
Use the `database/schema.sql` as the reference model and recreate equivalent tables in Supabase SQL editor.

Important changes when moving to Postgres:
- Replace `AUTO_INCREMENT` with `GENERATED BY DEFAULT AS IDENTITY`
- Replace `ENUM` columns with `TEXT CHECK (...)` constraints or `VARCHAR`
- Convert `TIMESTAMP DEFAULT CURRENT_TIMESTAMP` to `TIMESTAMP WITH TIME ZONE DEFAULT NOW()`
- Replace `ON DELETE CASCADE` style constraints with proper Postgres equivalents

### 3) Add auth model
- Use Supabase Auth for staff/admin accounts
- Keep the existing Express JWT middleware only as a transitional compatibility layer
- Eventually move user session verification to Supabase JWT validation or a custom server middleware

### 4) Replace direct DB access
- Keep the current MySQL files for legacy mode
- Add Supabase service calls in a dedicated `services` layer
- Prefer one repository/service abstraction that switches by config

### 5) Frontend auth flow
- Use Supabase client to sign in or sign up from the browser
- Store session with the Supabase client
- Use the Supabase access token in API requests when interacting with protected routes

### 6) Server-side strategy
For deployment readiness, prefer:
- Supabase for auth + database
- Express API as a thin service layer
- environment switching based on `SUPABASE_URL` and `SUPABASE_ANON_KEY`

## Files added for Supabase readiness
- `backend/src/config/supabase.js`
- `backend/src/services/databaseService.js`
- `backend/src/services/supabaseAuthService.js`
- `frontend/src/lib/supabase.js`

## Next migration step
Convert the app to a single abstraction layer like:
- `core/database.js`
- `core/auth.js`
- `services/*`

This will let the project run in either MySQL or Supabase mode without changing the UI contracts.
